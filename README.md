# OLCWave — Ghostlane / Remnawave fork

Этот форк сохраняет upstream [invdevv/olcwave](https://github.com/invdevv/olcwave) и лицензии авторов. Мы доработали реальный отзыв Ghostlane-доступов через Remnawave, поддержку нескольких изолированных серверов, устойчивый учёт квоты и календарный сброс лимитов.

**Начните с [безопасного запуска](docs/public-deployment.md), а не с upstream install.sh.** Приложению нужен отдельный Docker daemon: доступ к socket означает полный контроль над ним.

- [Полный список изменений и ограничения](docs/fork-changes.md)
- Проверено: Remnawave 3.4.5, Ghostlane CLI 1.0.466, HTTPS и отзыв скачанных ключей без refresh.
- Это companion-панель, не встроенный плагин Remnawave. Общая квота VLESS+Ghostlane и HWID Ghostlane не реализованы.

Панель управления для [OLCRTC](https://github.com/openlibrecommunity/olcrtc).

Работает в двух режимах:
- **С Remnawave** (`RW_ENABLED=true`) — пользователи и подписки синхронизируются с Remnawave
- **Без Remnawave** (`RW_ENABLED=false`) — полностью автономная работа, пользователи создаются локально

## Возможности

* **Интеграция с Remnawave** (опционально) - статус пользователя и срок действия подписки берутся напрямую из Remnawave. Опциональная фильтрация по squad - выдавайте подписки только участникам нужной группы
* **Автономный режим** - полноценная работа без Remnawave: создание пользователей через панель, ручное управление трафиком и подписками
* **Профили** - переиспользуемые YAML-шаблоны конфигурации OLCRTC [Примеры профилей](docs/сonfig_examples)
* **Автоматическая генерация конфигурации** - панель сама заполняет уникальные параметры для каждого пользователя (crypto.key, room.id итд)
* **Автоматическое создание комнат** - для некоторых провайдеров панель сама создаёт комнаты через их API. Больше не нужно вручную создавать комнаты и копировать ID. Просто укажите токен - комнаты будут создаваться автоматически для каждого пользователя. [Подробнее в docs/profiles.md](docs/profiles.md#Автоматическая-генерация-комнат)
* **Управление контейнерами** - запуск, остановка, перезапуск и удаление OLCRTC-контейнеров, просмотр логов в реальном времени и текущего `config.yaml`
* **Учёт трафика** - SOCKS-прокси внутри каждого контейнера считает переданные данные, backend собирает статистику по пользователям, контролирует лимиты и позволяет сбрасывать счётчики.
* **Routing** - маршрутизация трафика контейнеров через внешние прокси (SOCKS5, VLESS и др.) с помощью Xray-core. Направляйте трафик заблокированных сайтов через прокси, российские сайты - напрямую, остальные - за границу.
* **Подписки** - одна ссылка для каждого пользователя, которая возвращает пакет всех доступных локаций в формате, совместимом с OLCBox
* **Subscription Page** - страница для пользователей по подписочному URL: скачивание OLCBox, пошаговая инструкция, ссылка для копирования и советы. Браузер видит HTML, клиентское приложение - raw-конфигурации. [Подробнее](docs/subscription_page.md)


## Быстрый старт

Для запуска используйте отдельную VM и собственный Docker daemon. Не давайте
панели socket рабочего Docker-хоста: это полный доступ ко всем его контейнерам.

```bash
git clone https://github.com/erikfrish/olcwave.git
cd olcwave
```

Далее следуйте [публичной инструкции развёртывания](docs/public-deployment.md):
настройте приватные переменные, доверенный CA, HTTPS и соберите закреплённые
образы. Для нескольких серверов настройте отдельные rootless-daemon’ы и
точное соответствие тегов профилей узлам. Старый `install.sh` оставлен как
upstream-артефакт, но не является рекомендуемым запуском этого форка.



## Обзор архитектуры

```text
Панель администратора             Клиент пользователя

        │                                 │
        ▼                                 ▼
Frontend (React SPA)                /sub/{uuid}
        │                                 │
        └──────────────┬──────────────────┘
                       ▼
                Backend (FastAPI)
                       │
        ┌──────────────┼──────────────────────┐
        ▼              ▼                      ▼
   PostgreSQL     Remnawave API       Docker daemon
 (пользователи,  (ОПЦИОНАЛЬНО:       (запускает
  профили,        проверка            контейнеры
  трафик,         пользователя,       OLCRTC + XrayCore)
  routing)        срок действия)
                                               │
                                               ▼
                                      Контейнеры OLCRTC
                                    olcwave-<tag>-<uuid>
                                               │
                                     (при enabled routing)
                                               ▼
                                       olcwave-xraycore
                                        (Xray-core)
```

* **Frontend** - приложение на React + Vite. В production собирается в статические файлы и обслуживается Caddy. Включает валидацию YAML/JSON конфигураций на клиенте.
* **Backend** - FastAPI-приложение, которое отвечает за всю логику: аутентификацию, профили, опциональную работу с Remnawave, управление контейнерами через Docker Socket, генерацию подписок, routing через Xray-core и фоновый учёт трафика.
* **PostgreSQL** - хранит локальные данные пользователей, шаблоны профилей и конфигурацию routing.
* **Remnawave API** (опционально) - если включено, backend синхронизирует пользователей и проверяет подписки через Remnawave.
* **Docker** - backend собирает образ `olcrtc` и запускает отдельный контейнер для каждой пары "профиль - пользователь" на Docker-хосте. При включённом routing также управляет контейнером `olcwave-xraycore`.
* **OLCRTC** - основной транспорт. Каждый контейнер также запускает SOCKS-прокси, который сохраняет статистику трафика в `stats.json`. Backend периодически считывает эти данные.
* **XrayCore** (опционально) - контейнер с Xray-core, маршрутизирующий трафик OLCRTC через внешние прокси.

Подробное описание работы системы в [docs/architecture.md](docs/architecture.md).
